# 模块：一致性工具（selftest / shim / hooks / check-all / doctor / build-info）

**最后更新**：2026-11-07 · 对应提交 `1be35a4`

这一组命令的共同点：**只读检查优先、能修才写、判据是"渲染后逐字节比对"而不是"看起来像"**。它们替代了各仓过去手写的 `build-check.sh` / `review-loop-check.sh` 之类脚本。

## 关键文件

| 文件 | 职责 |
|---|---|
| `lib/selftest.mjs` | `--shims` / `--config` / `--lock` / `--peer` / `--exit-codes`（+ `--repos`）检查实现 |
| `lib/shim.mjs` | 模板渲染（`{{VERSION}}` / `{{CMD}}`）、6 入口定义、`install` 写入判定、`check` 逐字节比对 |
| `templates/shim.sh` | shim 的唯一模板 |
| `lib/hooks.mjs` | pre-push 钩子正文（含标记行）、目标路径推算、`install` / `check` |
| `lib/check-all.mjs` | 逐包跑 `pnpm test` / `pnpm run check` / `pnpm run typecheck`，串行执行、最后汇总 |
| `lib/doctor.mjs` | 多仓 `build.json` 比对（基准 = 第一个带标识的仓） |
| `lib/profile-check.mjs` | `doctor --profile` 的 7 项体检 |
| `lib/build-info.mjs` | 读 `build.json` → `{gitSha, builtAt, dirty}` 或 `null`（源码目录） |

## `selftest`

```bash
dsh-pipeline selftest [--shims] [--config] [--lock] [--peer] [--exit-codes] [--fast | --repos a,b,c] [--json] [--root <dir>] [--dsh-version <v>]
```

| 检查项 | 内容 | 状态 |
|---|---|---|
| `--shims` | `<root>/scripts/pipeline` 下 6 个入口 == 按**当前包版本**渲染后的模板 | 已实现 |
| `--config` | `<root>/.dsh/pipeline.json` 能被 schema 接受、无未声明字段；没有该文件视为通过 | 已实现 |
| `--lock` | 装包的 `build.json` == `.dsh/pipeline.lock.json` 的 `expect`；锁不存在 / 未装包跳过，旧版本包或不一致失败（详见下节 `lock`） | 已实现 |
| `--fast` | 等价 `--shims --config`（pre-push 用，契约 §9） | 已实现 |
| `--repos a,b,c` | 多仓装的共享包是否同一构建（读各自 `tools/node_modules/dsh-pipeline/build.json` 的 `gitSha`） | 已实现 |
| `--peer` | 各包的 DSH 版本声明覆盖当前版本（四个来源按优先级） | 已实现 |
| `--exit-codes` | 起子进程真跑七条用例，断言契约 §4：APPROVE 记录过闸门→0；REJECT 记录、旧规则记录（`E_POLICY_VERSION`）→1；缺参/未知参数/未知子命令→2；入口找不到共享包→3（并断言输出关键字）；cwd 钉临时目录 | 已实现（唯一会 spawn 的检查项） |

- `--repos` 与 `--shims` / `--config` / `--lock` / `--peer` / `--exit-codes` / `--fast` **互斥**（两者的 `--json` 形态不同）；
- `--repos` 的路径：绝对路径直接用、相对路径按 `--root`（缺省当前目录）、`~/` 展开；
- `--repos` 的纳入条件：目录存在 + 有 `bin/cli.mjs` + `build.json` 可读；其余**跳过并列出**（目录不存在 / 不是目录 / 未装包）；
- 可比对的仓**不足 2 个** → `baseline = null`、`ok = true`（没有第二方就没有"不一致"可言）；
- `--root` 缺省：显式 > 主工作区 > 当前目录（与 `record` / `review` / `status` / `shim` / `hooks` 同一口径 `resolveMainWorktreeRoot`）。

## `lock`

```bash
dsh-pipeline lock write --root <仓>   # 从装包 build.json 写 .dsh/pipeline.lock.json（= 刷新锁）
dsh-pipeline lock check --root <仓>   # 与 selftest --lock 同一实现
```

| 项 | 规则 |
|---|---|
| 锁文件 | `<仓>/.dsh/pipeline.lock.json`，内容只有 `{"expect":"<sha7> <builtAt>"}`；多余字段、格式不合规都算失败 |
| 写 | 只认**装包位置** `tools/node_modules/dsh-pipeline/build.json`；未装包 / 旧版本包（没有 build.json）→ 退 2，不写假 pin |
| 读 | `checkLock` 同时被 `lock check` 与 `selftest --lock` 使用，输出口径一致 |
| 跳过 | 锁不存在、或装包目录不存在 → 跳过（退 0） |
| 失败 | 旧版本包（无法证明）→ 1；锁与装包不一致 → 1（detail 同时给两边的值）；锁格式非法 → 1 |
| 路径错 | `--root` 不存在或不是目录 → 退 2（不是静默跳过） |
| 不手改 | 手工编辑绕过校验；`+dirty` 之类打包态信息不进锁（`formatExpect` 只取 sha7 + builtAt）；锁里写 40 位全 sha 也算格式错 |

## `shim`

```bash
dsh-pipeline shim install [--root <dir>] [--force]   # 生成 6 个入口，0755
dsh-pipeline shim check [--root <dir>]               # 渲染后逐字节比对
```

| 入口文件 | 转发到 |
|---|---|
| `pipeline.sh` | 空（原样透传第一个参数） |
| `new-task.sh` | `task` |
| `open-pr.sh` | `pr` |
| `merge-pr.sh` | `merge` |
| `review.sh` | `review` |
| `status.sh` | `status` |

- 模板头：`# GENERATED by dsh-pipeline v{{VERSION}} — do not edit.`；
- 模板内容：按 `$0` 文件名推导子命令 → 定位仓根 → 推导主工作区 → 按 `$DSH_PIPELINE_HOME` → 主工作区 `tools/` → 仓 `tools/` 找包 → 把 `-C <dir>` 翻译成 `--root <dir>` → `exec node <cli> <CMD> "$@"`；
- 找不到包：stderr 打印试过的路径，**退出码 3**；
- `install` 是两段式：先对全部入口做「相同 / 不同 / 缺失」判定，**有冲突且没 `--force` 时一个文件都不写**（半装状态比明确失败更难排查）；
- `check` 的判据固定为「用当前包版本渲染模板后逐字节比对」——文件头内嵌版本号，直接比模板原文会永远假红；
- 权限：`writeFileSync` 的 mode 会被 umask 吃掉，所以显式 `chmodSync(0o755)`。

## `hooks`

```bash
dsh-pipeline hooks install [--root <dir>] [--force] [--allow-main]
dsh-pipeline hooks check [--root <dir>]
```

| 项 | 规则 |
|---|---|
| 目标路径 | 主仓 `git rev-parse --git-common-dir` 下的 `hooks/pre-push`；**若设了 `core.hooksPath` 就装到那里**（否则装进 `.git/hooks` 会静默不生效）；`~/` 前缀会展开（git 自己也会展开） |
| 拦截逻辑 | 读 stdin 每行 `<local_ref> <local_sha> <remote_ref> <remote_sha>`，`remote_ref` 是 `refs/heads/main` 或 `refs/heads/master` 就拒绝（stderr 一行 + 退出 1），其余放行 |
| 标记行 | `# GENERATED by dsh-pipeline hooks install — do not edit`；带它才允许覆盖，`check` 也据此识别自家文件 |
| 四种 install 结果 | 不存在 → `installed`；内容相同 → `unchanged`（只补权限）；内容不同但带标记行 → `updated`；别人的钩子 → **拒绝**（退 1，`--force` 才覆盖） |
| `--allow-main` | 装一个不拦截的版本（确实需要直推的仓）；`check` 认两种变体 |
| `check` 的额外判定 | 内容一致但**没有可执行位**也算不一致（钩子根本不会跑，报"一致"就是假绿） |
| bash 兼容 | 用 macOS 自带 3.2 语法：默认值一律 `if [ -z ... ]` 判断，不用 `${VAR:-默认}` |

## `check-all`

```bash
dsh-pipeline check-all [--root <dir>] [--packages a,b,c] [--json]
```

| 项 | 规则 |
|---|---|
| 包来源 | `--packages` > 配置 `checks.packages`（按给定顺序，不自动发现）> 自动发现（`<root>` 下每个含 `package.json` 的子目录，跳过 `node_modules` 与 `.` 开头的目录，按名称排序）再按 `checks.exclude` 过滤 |
| 检查项 | 有 `scripts.test` → `pnpm test`；有 `scripts.check` → `pnpm run check`；有 `scripts.typecheck` → `pnpm run typecheck` |
| 缺 `node_modules` | 三项都记「跳过（未安装依赖）」，**不算失败**（先于脚本判定） |
| 有依赖但三项脚本都没有 | 「失败（无可跑检查）」 |
| 包目录不存在 / 无 `package.json` / 解析失败 | 记失败（单项 `-`） |
| 执行 | **严格串行**，任一失败不中断，最后汇总；命令自身输出不透出，每项一行 `<包目录> \| <检查> \| <结果>`（失败时把输出缩进两格打印） |
| 汇总口径 | 按包计：任一项失败 → 包失败；全跳过 → 跳过；否则通过 |
| 退出码 | 0 全通过（含全跳过）/ 1 有失败 / 2 用法错误 / **3 找不到 pnpm**（环境错误，不计入通过/失败） |

## `doctor`

```bash
dsh-pipeline doctor [--repo a,b] [--json] [--expect <sha>] [--profile <dir>]
```

**构建段**：对每个仓读 `<root>/tools/node_modules/dsh-pipeline/build.json`。

| 仓的状态 | 输出 |
|---|---|
| `package.json` 的 name 以 `/dsh-pipeline` 结尾（或 `dsh-pipeline`） | `源码目录（未打包）` |
| 没有安装目录 | `未安装` |
| 装了但无 `build.json`（旧包） | `已安装（无构建标识：旧版本包，需重新打包并刷新）` —— **有基准时算漂移** |
| 正常 | `<gitSha 前 7 位>[+dirty] <builtAt>` |

- 基准 = 第一个带构建标识的仓；`--expect` 允许传短 sha（双向前缀匹配）；
- 全部是源码目录 → 构建视为通过（不看 `--expect` / 漂移）；
- 有基准但某仓无标识 → 漂移（能区分"没装"与"装了但没标识"）。

**profile 段**（`--profile <dir>`，缺省 dir 按 `$DSH_HOME/profiles/web`）：7 项，逐项 ✓ / ✗ / `-`（跳过），任一 ✗ 整体退 1。

| # | 检查项 | 判据 |
|---|---|---|
| 1 | profile 里已无旧包 `dsh-plugin-product-subagents` | `package.json` 里不含 `"<旧包名>"` |
| 2 | profile 里有新包 `dsh-plugin-subagents` / `dsh-subagents` | 同上 |
| 3 | `node_modules/dsh-plugin-subagents` 软链有效 | `lstat` 是软链 + 解析目标存在且是目录 |
| 4 | `dsh --dump-config` 能看到新包 | 真实跑 `dsh --profile <名> --dump-config`；**dsh 不在 PATH 时跳过、不算失败** |
| 5 | `cordis.patch.yml` 存在且非空 | 只看 size，不读内容 |
| 6 | 审核记录目录可写 | 逐仓 `mkdir -p <root>/.dsh-web/reviews` + `access(W_OK)` |
| 7 | profile 目录存在 | 顺带报告 `DSH_HOME` |

**红线**：profile 文件里可能有 secret——只判断包名字符串与文件存在性 / 大小 / 软链指向，**不打印、不回显文件内容**。

## `build-info`

`readBuildInfo()`：源码目录没有 `build.json`（在 `.gitignore` 里）→ 返回 `null`，直接跑源码是正常用法，不报错。`describeBuild()` 给 `--version` 用（输出 `<版本> (<sha7>[+dirty] <builtAt>)` 或源码说明）。

## 依赖

`selftest` → `config` + `shim`；`shim` → `templates/shim.sh` + `record.mjs`（`PACKAGE_VERSION`）；`hooks` → `git.mjs`；`check-all` → `node:child_process`；`doctor` → `build-info` 语义（自己读 JSON）；`profile-check` → `node:child_process`。

## 修改本模块的注意事项

1. **改模板要重新 `shim install`**，否则所有消费仓 `selftest --shims` 红。
2. **不要放宽 `check` 的判据**（渲染后逐字节、比执行位），否则会出现"检查通过但不生效"的假绿。
3. **`--repos` 不足 2 个必须退 0**：CI 里没有兄弟仓，判失败会让 CI 必红。
4. **`check-all` 缺依赖必须算跳过**：否则没装依赖的仓会永远红。
5. **`profile-check` 不要打印文件内容**，也不要为了"更精确"去解析 profile JSON 全文。
6. **新检查项先加契约**（§9 表格），再实现；目前没有未实现的检查项，`PENDING_CHECKS` 为空。
