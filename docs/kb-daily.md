# 知识库日更（kb daily）runbook

**Updated:** 2026-11-15

> 本文是**运维流程**，不是命令参考。参数与退出码看 `docs/CONTRACT.md` §3.2 / §4；实现细节看 `docs/knowledge-base/modules/kb.md` 的「日更队列」节。

## 它解决什么

代码改了，文档就该跟着改。以前靠一个**永久滚动 issue** 收提醒（#173 / #196 / #73 / #252）：没人负责改，也没规定什么时候关；issue 正文还写着「处理完请关闭」，而关了以后第二天的评论照样投得进去，水位照推、退出码 0，异常完全不可见。

现在改成**每天一个追踪 issue，当天修完当天关**。「关闭」从「等人想起来」变成流程的最后一步。

## 谁在跑

- DSH 定时任务 `schedule-8f16f710-f209-4256-a574-a94e555cd27a`，每天 09:30（Asia/Shanghai），`target: new`，每天一个干净会话。
- `cwd` 固定 `/Users/gubin/workspace/research`：这条链路跨四个仓，不属于其中任何一个，research 是这条线的计划/文档区，会话产物（报告、临时笔记）落在那里，不污染业务仓。
- 宿主没在跑当天就不触发，恢复后区间自然变长，重扫不漏，**不需要补跑历史日期**。

## 一天长什么样

对每个有知识库的仓，按顺序：

1. **算影响**：`dsh-pipeline kb queue --root <仓> --repo <owner/name> --daily`
   - 无影响 → 静默退 0，**不建 issue**（没活的日子不产生噪音）。
   - 当天 issue 已存在且开着 → 复用（重入安全）。
   - 当天 issue 已关闭 → 打印「今日已完成」，退 0，跳过。
   - 昨天还有没收口的单 → 先在旧单补一条「未收口，转入今日 #N」并关掉，再往今天的单上投。
2. **修文档**：把清单交给 executor 子代理，在**任务分支**上：
   - `dsh-pipeline task <issue号>` 建 worktree；
   - `dsh-pipeline kb refresh --root . --doc <文档>` 取提示词，按提示词重写；
   - 重打页眉的 commit stamp（取**本次内容所对齐的代码提交**，不是文档提交本身；squash 后悬空的 sha 会被 `kb check` 判 `E_STAMP_ORPHAN`）；
   - 本仓门禁（`node --test` / `kb check --strict`）过绿；
   - `dsh-pipeline pr` 开 PR（body 首行 `Closes #<issue号>`）。
3. **审核**：reviewer 子代理给判定。
   - `APPROVE` → `dsh-pipeline merge --pr <n> --record <记录>`。
   - `REJECT` → 回第 2 步，最多 3 轮；3 轮不过就停手，在 issue 里写明卡在哪。
   - 落记录必须**如实标注**：`review publish --model glm-5.3-flash --provider codebuddy --form B`。不带这三个旗标会落成 `unknown`，事后无法追溯是谁审的。
4. **收口**：`dsh-pipeline kb queue --repo <owner/name> --finish`
   - 关当天 issue；
   - 把投递时记下的 `pending` 提升为水位。

## 三条不能省的规矩

1. **水位只在 `--finish` 时前进**。贴提醒只写 `pending`。这样「提醒过」和「修好了」是两个状态，不会出现「issue 关了但文档没改，水位却过去了」。
2. **没修完就不 `--finish`**。第二天的新单会把同一批再列一次——**重复，但不丢**。旧单会被次日流程自动关掉并指向新单，不会堆积。
3. **这条链路只放行知识库文档改动**。碰到代码、配置、`.gitignore`、lockfile，一律回退成「人工处理」，不要为了让它自己跑通去放宽范围。

## 失败与兜底

| 现象 | 处理 |
|---|---|
| `gh` 报 401 / 无权限 | 沙盒读不到钥匙串，不是令牌过期。原样记录，**不要** `gh auth login`；在完整权限下重跑 |
| 当天修不完（改动大 / 生成结果不对 / review 打回 3 轮） | 不 `--finish`；在 issue 里写清卡在哪；次日新单会重列同一批 |
| 昨天的单还开着，今天又跑了 `--daily` | 命令自动补评论并关旧单，再投今天的；不会堆历史 issue |
| 当天 issue 被人手动关了 | 明天按「今日已完成」跳过；水位没前进的话，后天会把同一批再列一次（安全方向，不丢） |
| CI 红 | 不合并，修到绿为止。共享包版本不动时消费仓不需要刷新构建 |
| 同一天跑了两遍 | 复用当天 issue，清单会重复贴一次；不影响水位与收口 |

## 换仓 / 停更

- **新增仓**：`.dsh/pipeline.json` 加 `repo`，手工跑一次 `--daily --since <HEAD>` seed 水位，再把仓加进定时任务。
- **某仓停止维护**：从定时任务 prompt 删掉该仓；当天 issue 若还开着，手工关掉并写明原因。
